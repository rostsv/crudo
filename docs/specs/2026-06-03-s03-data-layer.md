# Spec — S03: Data Layer (Repo Contracts + In-Memory Impls + Seed)

**Status:** approved (design) · **Spec S03 (logic)** · depends on S02 · scope = repository **interfaces** in `domain/repositories/`, **in-memory implementations** in `data/`, the bundled product seed (first DTO + mapper), id generation, DI wiring, and the architecture-test extension for the new layers. No widgets, no engines, no Supabase.

## Goal
Give every later spec a working, swappable persistence story: controllers program against domain repository interfaces; in-memory impls (reactive, seeded) serve until Supabase replaces them behind the **unchanged contract** at S20.

## Decisions (brainstorm 2026-06-03)
- **API shape: Futures + watch Streams.** CRUD as `Future`s plus `watch*()` broadcast streams so controllers are reactive (Today auto-updates on edits). Maps 1:1 to Supabase realtime at S20. In-memory = `StreamController.broadcast` + in-place `Map` stores.
- **User scoping: fixed local user.** `const localUserId = 'local'` (data layer); `UserProfile(id: localUserId)` auto-seeded on first access. S22 swaps the id source to `auth.uid` — interfaces unchanged.
- **Seed: authored by Opus, transcribed verbatim.** ~60 curated whole foods (USDA-typical per-100g macros, all 8 categories) shipped as `assets/seed/products.json`. Seed ids are stable readable strings (`seed-chicken-breast`); user-created ids are uuid v7.
  - **Forward-looking (S20+):** the product catalog becomes a server table (global rows, `user_id null`), fetched on install + refreshed ~daily when online. No interface change — the repo stays the source of truth; the bundled JSON is just the initial cache.
- **IDs: `uuid` package (^4.x, v7) behind an `IdGenerator`** exposed via a Riverpod provider — tests override with deterministic ids. Domain stays pure (no uuid import under `lib/domain/`).
- **Soft-delete semantics:** `delete(id)` removes the item from all queries; already-materialized day snapshots are unaffected (detached). Whether deletion is soft or hard *in storage* is an impl detail until S20 (DDL uses `deleted_at`).
- **DI composition root: `lib/config/di.dart`.** Repo providers (`Provider<ProductRepository>` etc.) wire interfaces → in-memory impls there. UI imports `config`, never `data` directly. S20 changes only this file.

## Repository interfaces (`lib/domain/repositories/`)
Pure abstract classes; return domain types; no Flutter/Riverpod imports (architecture test enforces).

```dart
abstract class ProductRepository {
  Stream<List<Product>> watchAll();          // seed + user products, deleted excluded
  Future<List<Product>> getAll();
  Future<Product?> getById(String id);
  Future<void> save(Product product);        // upsert by id
  Future<void> delete(String id);            // disappears from queries; snapshots unaffected
}

abstract class MealTemplateRepository {
  Stream<List<MealTemplate>> watchAll();
  Future<List<MealTemplate>> getAll();
  Future<MealTemplate?> getById(String id);
  Future<void> save(MealTemplate template);
  Future<void> delete(String id);
}

abstract class PlanTemplateRepository {
  Stream<List<PlanTemplate>> watchAll();
  Future<List<PlanTemplate>> getAll();
  Future<PlanTemplate?> getById(String id);
  Future<void> save(PlanTemplate plan);
  Future<void> delete(String id);            // ≥1-plan rule is S09 logic, not repo's
}

abstract class DayRepository {
  Stream<Day?> watchByDate(DateTime date);   // date = UTC-midnight local-date label
  Future<Day?> getByDate(DateTime date);
  Future<List<Day>> getRange(DateTime from, DateTime to);  // inclusive; history/calendar
  Future<void> save(Day day);                // upsert by date
}

abstract class ProfileRepository {
  Stream<UserProfile> watch();
  Future<UserProfile> get();                 // auto-seeds UserProfile(id: localUserId)
  Future<void> save(UserProfile profile);
}

abstract class StreakRepository {
  Stream<Streak> watch();
  Future<Streak> get();                      // defaults to const Streak()
  Future<void> save(Streak streak);
}
```

## In-memory impls (`lib/data/repositories/`)
`InMemory*Repository` per interface: `Map<String, T>` (Days keyed by date label), `StreamController.broadcast` emitting current snapshot on every mutation **and on listen** (late subscribers get current state — match Supabase-realtime-with-initial-fetch behavior). `InMemoryProductRepository` takes the seed list in its constructor and overlays user products.

## Seed pipeline (`lib/data/`)
- `assets/seed/products.json` — authored in the plan, registered in `pubspec.yaml` assets.
- `data/dto/product_dto.dart` — **first DTO**: manual `fromJson` (Map → fields). No json_serializable (stays out of the project until codegen is justified at S20).
- `data/mappers/product_mapper.dart` — `ProductDto → Product` (`isCustom: false`).
- `data/services/seed_service.dart` — loads the asset via `rootBundle`, decodes, maps; one external system (bundled assets), one wrapper.

## Id generation (`lib/data/services/id_generator.dart`)
```dart
class IdGenerator { String newId() => const Uuid().v7(); }
final idGeneratorProvider = Provider<IdGenerator>((ref) => IdGenerator());
```
(`uuid ^4.5.x` runtime dep — supports v7.) Consumers: controllers/use-cases creating Products/Meals/Plans/instance Meals (S05+).

## DI (`lib/config/di.dart`)
`Provider<XxxRepository>` per repo, typed as the **interface**, constructed with in-memory impls; `productRepositoryProvider` is async-aware of the seed (`FutureProvider`/eager load at bootstrap — implementer detail, documented in plan). `localUserId` const lives in `lib/data/local_user.dart`.

## Architecture-test extension (`test/architecture/dependency_rules_test.dart`)
Add layers to the allowlist map:
- `lib/data` → `dart:*`, `package:crudo/domain/`, `package:crudo/data/`, `package:flutter/services.dart` (rootBundle), `package:flutter_riverpod/`, `package:uuid/`.
- `lib/config` → `dart:*`, `package:crudo/` (composition root may see all), `package:flutter/`, `package:flutter_riverpod/`.
- `lib/domain` rule unchanged — still cannot import data/uuid/Riverpod.

## Tests (`test/data/`, extend `test/architecture/`) — `package:checks`
- Per repo impl: save→get round-trip; upsert overwrites; delete removes from `getAll`/`watchAll`; `watch*` emits on listen + after each mutation (use `expectLater`/stream queues); Day keyed by date label (`getByDate` with a different time-of-day label misses).
- Seed: `SeedService` parses the real asset (count == authored count, spot-check 3 known products' macros); `ProductDto`→`Product` mapping (`isCustom` false).
- Profile/Streak: auto-seed defaults on first `get()`.
- IdGenerator: emits valid non-repeating ids (uuid shape).
- Architecture test green with new layer rules.
